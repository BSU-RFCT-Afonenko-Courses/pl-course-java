Сложность: Высокий

Реализуйте DynQueue<T> с методами void put(T value) и T get() и порядком извлечения FIFO. Хранилище — массив. Когда свободного места не хватает для добавления, создавайте больший массив, сохраняя порядок оставшихся элементов.

Конструктор принимает непустой массив T[]. Новая очередь пуста независимо от исходного содержимого массива. После передачи клиент не использует массив напрямую; фактический тип его компонента совпадает с аргументом типа очереди. Добавляемые элементы отличны от null. Проверять эти предпосылки программно не требуется.

При пустой очереди get выводит сообщение и возвращает null, сохраняя состояние. Текст сообщения об отказе и коэффициент увеличения массива выбирайте самостоятельно. Другие сообщения демонстрационной программы допустимы. Для увеличения можно использовать Arrays.copyOf: Arrays.copyOf для ссылочных компонентов. Это один из допустимых способов; размещение элементов может быть линейным или кольцевым.

Продемонстрируйте несколько увеличений вместимости, чередование добавления и извлечения и работу с двумя типами элементов. Подберите действия для нескольких увеличений с учётом выбранного способа роста. Предъявите исходник и объясните связь типов, начальную пустоту и сохранение порядка при изменении хранилища. Поля и устройство демонстрации выбирайте самостоятельно. [1]

Сохраните обязательные сигнатуры открытого класса Study из канонического стартера, без объявления пакета. Решение можно разместить в нём или вызвать из него свои классы и методы. Дополнительный класс запуска и фиксированный формат демонстрации не требуются.

Обобщённый вход Study<T> из стартера не ограничивает тип элемента сравнимыми или числовыми типами. Создание получает массив T[] и на допустимых данных успешно; объявление проверяемого исключения конструктора разрешено. Внутренний конструктор может иметь дополнительные параметры, обобщённую форму или varargs, если получает требуемый массив. Каждый экземпляр имеет собственное состояние.

Переданный массив имеет положительную длину и фактический тип компонента, соответствующий аргументу типа контейнера; для Study<Number> используется Number[]. Оболочка передаёт этот же массив внутреннему контейнеру, если он выделен в отдельный класс. Исходные значения ячеек не являются элементами нового контейнера. Возвращаются помещённые ссылки. Клиент после передачи не обращается к массиву напрямую и не добавляет null. Проверять нарушения этих предпосылок не требуется. В исходнике и объяснении сохраняется работа с T[] и его фактическим типом при выполнении.

Операции put и get из стартера вызывают ваш DynQueue<T> или наследуют его операции с доступностью для проверки. Внутренняя видимость, наследованные и эквивалентные обобщённые операции свободны.

Начальное хранилище связано с переданным массивом и его фактическим типом компонента. При нехватке места создаётся больший массив, который допускает значения типа элемента; оставшиеся элементы сохраняют ссылки и FIFO-порядок. Уже извлечённые элементы после роста не возвращаются. Добавление при нехватке места должно успешно увеличивать хранилище в пределах доступной памяти. При пустой очереди get сообщает об отказе, возвращает null и сохраняет состояние. Сообщение содержит непустой текст в стандартном выводе либо стандартном потоке ошибок; точный текст, число строк и дополнительные сообщения свободны.

Коэффициент роста, линейное или кольцевое размещение и способ создания большего массива свободны. Arrays.copyOf допустим, но не обязателен. Продемонстрируйте несколько фактических увеличений, подобрав последовательность для выбранного способа роста, и работу с двумя типами. Метод получения вместимости и фиксированное число увеличений на тестовой последовательности не требуются.

Открытые примеры

FIFO при росте для двух типов. В очередь на String[2] поместите А, Б, В, извлеките один элемент, добавьте Г и извлеките оставшиеся три. Последовательность извлечений — А, Б, В, Г. В очереди на Integer[2] поместите 10, 20, 30, извлеките один элемент, добавьте 40 и извлеките ещё три: получатся 10, 20, 30, 40.

Начальная пустота. После передачи Integer[]{99} новая очередь пуста: get() возвращает null и выводит сообщение об отказе.

Помещение сверх начальной длины. В очередь на массиве Integer[]{99} последовательно поместите 7 и 8. Два извлечения возвращают 7, затем 8.

После опустошения. Когда 7 и 8 извлечены из этой очереди, следующий get() возвращает null и выводит сообщение об отказе; текст сообщения свободен.

Сдайте Study.java без объявления пакета, сохранив объявления входа из стартера.
