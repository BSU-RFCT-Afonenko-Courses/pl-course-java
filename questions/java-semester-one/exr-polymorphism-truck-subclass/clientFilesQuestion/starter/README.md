Создайте `Vehicle` с закрытыми целочисленными полями `passengers`, `fuelcap`, `mpg`: число пассажиров неотрицательно, запас топлива в галлонах и пробег в милях на галлон положительны. Предусмотрите конструктор, чтение и изменение характеристик с проверкой этих ограничений, `range()` для дальности и `fuelNeeded(int miles)` для расхода топлива типа `double`. Расстояние неотрицательно; произведения помещаются в `int`. Для базовых операций используйте открытые сигнатуры из [Упражнение 17.2](https://bsu-rfct-afonenko-courses.github.io/Java/tasks/bank/polymorphism.html#exr-polymorphism-vehicle-interface); дальность равна `fuelcap * mpg`, топливо — отношению `miles` к `mpg` с абсолютной погрешностью не больше `1e-6`. Реализация самого интерфейса `IVehicle` в этой карточке необязательна.

Подкласс `Truck` добавляет закрытое поле `cargocap` — неотрицательную грузоподъёмность в фунтах. Реализуйте конструктор `Truck(int p, int f, int m, int c)`, методы `int getCargo()` и `void putCargo(int c)`. Покажите использование унаследованных операций без открытия базовых полей.

Неверные параметры конструктора, метода изменения или отрицательное расстояние отклоняются через `IllegalArgumentException`. Метод изменения проверяет значение до записи: после отказа все характеристики прежние.

Покажите обычный `Vehicle(2, 10, 25)`: дальность 250, топливо для 50 миль 2.0; отказ изменения `fuelcap` на `0` сохраняет дальность 250, отрицательное расстояние вызывает исключение. Для `Truck` отдельно покажите отказ отрицательной грузоподъёмности.

Предъявите исходники и объясните, как подкласс использует закрытое состояние базового класса и почему отказ изменения оставляет характеристики прежними.
