Сложность: Высокий

Это один из двух вариантов обязательного выбора: выполните эту задачу либо «Сброс очередей через общий интерфейс».

Используйте полный Очереди символов. Каждая задача самостоятельна: создайте три реализации по этому договору либо используйте собственные ранее написанные реализации.

Создайте метод static void transfer(ICharQ source, ICharQ destination, int count), переносящий count элементов между очередями. Содержащий его класс выбирайте самостоятельно.

Предусловия: ссылки не равны null, объекты различны, count >= 0. Значение count равно числу элементов источника. Приёмник пуст и допускает count успешных помещений; для линейной FixedQueue учитываются оставшиеся неиспользованные позиции. Проверять нарушение этих предусловий не требуется. Вызывающий код знает count, поскольку сам заполняет источник.

После переноса источник пуст, приёмник содержит те же символы в том же порядке. Метод пользуется только операциями ICharQ, сохраняет сами объекты очередей и ничего дополнительно не печатает. Для пустого источника с count = 0 обе очереди остаются пустыми.

Предъявите исходники и консольную демонстрацию разных пар реализаций и случая count = 0; наблюдайте обе очереди после переноса. Покажите общий интерфейсный клиент для трёх реализаций. Объясните, откуда известен count, достаточно ли неиспользованных позиций у линейного приёмника и как учитываются различия очередей.

Объясните, почему клиент может принять новую реализацию без новой ветви instanceof и почему для DynQueue не требуется отказ переполнения. Вспомогательные поля, методы и способ запуска свободны в пределах общего договора. Требуются интерфейсный клиент и закрытое массивное FIFO-хранение.

Вход для воспроизводимой проверки

Обязательные объявления входа заданы в стартере; сохраните их и свяжите со своим решением. Собственные классы, видимость, вспомогательные методы и алгоритмы выбирайте в пределах условия. Если предметный API уже обеспечивает этот вход, дополнительный класс не требуется.

Через файловый диалог сдайте файлы CircularQueue.java, DynQueue.java, FixedQueue.java, ICharQ.java и Study.java из src/main/java стартового проекта. Во всех файлах пакет не объявляйте. Вспомогательные классы и методы можно определить в этих файлах; демонстрацию можно разместить в одном из них, без дополнительного исходника.

Открытые примеры

Выросший источник и кольцевой приёмник. Источник DynQueue(2) содержит A, B, C; приёмник CircularQueue(3) пуст. Перенесите 3 элемента. Перенос ничего не печатает, из приёмника извлекаются A, B, C. Следующий get() из источника возвращает \0 и печатает «Очередь пуста».

Нулевой перенос. Источник CircularQueue(1) пуст. В приёмник FixedQueue(1) ранее поместили Q и извлекли его, поэтому очередь пуста, а линейное место уже исчерпано. Перенос 0 элементов молчит и оставляет обе прежние очереди пустыми, без сброса или нового помещения.
