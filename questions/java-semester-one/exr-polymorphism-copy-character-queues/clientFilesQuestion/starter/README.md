Используйте полный [Очереди символов](https://bsu-rfct-afonenko-courses.github.io/Java/tasks/bank/polymorphism.html#sec-bank-character-queues). Каждая задача самостоятельна: создайте три реализации по этому договору либо используйте собственные ранее написанные реализации.

Создайте метод `static void transfer(ICharQ source, ICharQ destination, int count)`, переносящий `count` элементов между очередями. Содержащий его класс выбирайте самостоятельно.

Предусловия: ссылки не равны `null`, объекты различны, `count >= 0`. Значение `count` равно числу элементов источника. Приёмник пуст и допускает `count` успешных помещений; для линейной `FixedQueue` учитываются оставшиеся неиспользованные позиции. Проверять нарушение этих предусловий не требуется. Вызывающий код знает `count`, поскольку сам заполняет источник.

После переноса источник пуст, приёмник содержит те же символы в том же порядке. Метод пользуется только операциями `ICharQ`, сохраняет сами объекты очередей и ничего дополнительно не печатает. Для пустого источника с `count = 0` обе очереди остаются пустыми.

Предъявите исходники и консольную демонстрацию разных пар реализаций и случая `count = 0`; наблюдайте обе очереди после переноса. Покажите общий интерфейсный клиент для трёх реализаций. Объясните, откуда известен `count`, достаточно ли неиспользованных позиций у линейного приёмника и как учитываются различия очередей.

Объясните, почему клиент может принять новую реализацию без новой ветви `instanceof` и почему для `DynQueue` не требуется отказ переполнения. Вспомогательные поля, методы и способ запуска свободны в пределах общего договора. Требуются интерфейсный клиент и закрытое массивное FIFO-хранение.
