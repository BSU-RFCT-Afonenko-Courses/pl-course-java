Для вывода результатов создайте новый каталог и файл средствами класса File. Сохраните в файл записи о телефонах и их владельцах. Выведите в файл отобранные записи, телефоны в которых начинаются с префикса k или j.

Формат UTF-8: одна запись в строке, телефон и владелец разделены точкой с запятой; например «291234567;Анна», «331234567;Борис», «441234567;Вера». Телефон храните строкой; k и j — строковые префиксы «29» и «33». Порядок результатов совпадает с порядком записей.

Телефон состоит из цифр ASCII, имя владельца непустое и не содержит ;, CR и LF. Префиксы k и j — непустые строки цифр, передаваемые вместе с именами файлов выбранным вами способом. В отбор входит запись, телефон которой начинается хотя бы с одного префикса. Совпадение с обоими не дублирует запись. Сохраните выбранные строки в том же формате UTF-8. Покажите совпадающие префиксы, отсутствие результатов и повторную запись: повтор входа сохраняется в результате, если проходит отбор.

Предъявите исходник, сохранённые записи, префиксы и файл отбора. Покажите создание каталога и файла средствами File; объясните, почему два совпавших префикса не удваивают запись.

Вход для воспроизводимой проверки

Сохраните обязательные сигнатуры входов из стартера. Они связывают проверку с вашим решением; наблюдаются его фактические действия и результаты. Формат отчёта и диагностики выбирайте в пределах условия.

Открытые примеры

В файле записаны по порядку 291234567;Анна, 331234567;Борис, 441234567;Вера. При k = 29, j = 33 новый выход в новом каталоге содержит первые две записи в исходном формате и порядке.

Для входа 291234567;Анна\n291234567;Анна\n441234567;Вера\n при k = 29, j = 29 результат содержит ровно два вхождения 291234567;Анна. Здесь \n обозначает LF; совпадение префиксов не удваивает каждое вхождение, а повторы исходной записи сохраняются.
