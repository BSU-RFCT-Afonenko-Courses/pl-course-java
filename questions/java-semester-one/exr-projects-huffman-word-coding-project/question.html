Сложность: Высокий · Время: 240 мин

Напишите программу, которая подсчитывает частоты слов английского текста и строит для них двоичный префиксный код по алгоритму Хаффмена. Ни один код слова не должен быть началом кода другого слова: это позволяет однозначно восстановить последовательность слов по таблице и битам. Для двух и более различных слов оптимальный код минимизирует суммарную длину закодированного текста при данных частотах среди двоичных префиксных кодов.

Подготовка: классы (Глава 11), коллекции (Глава 18) и очередь с приоритетами. Перед реализацией разберите построение дерева Хаффмена на небольшой таблице частот и получение кода по пути от корня к листу. Для построения дерева используйте PriorityQueue. Другие задачи добровольного раздела предварительно выполнять не требуется.

Вход и результат

Исходный текст: one two two three three three. Единицы кодирования — слова, разделённые пробелами; регистр сохраняется. Выведите таблицу «слово — частота — код» и последовательность символов 0 и 1, полученную заменой каждого слова его кодом в порядке входа. Двоичный файл и отдельная реализация записи битов не требуются.

При равных частотах применяйте выбранный воспроизводимый порядок и объясните его. Дерево и коды слов определяются вашим алгоритмом с учётом этого порядка.

Отдельные граничные случаи:

  • пустой вход даёт пустую таблицу и пустой кодированный текст;
  • если различное слово только одно, ему назначается код 0; каждое вхождение этого слова даёт один ноль;
  • слова с равными частотами обрабатываются по выбранному воспроизводимому правилу, сохраняя префиксность и оптимальную суммарную длину.

Предъявите исходники и назовите выбранный порядок при равных частотах до сравнения результатов. На исходном тексте и граничных случаях сопоставьте частоты, таблицу кодов и полученную последовательность битов. По таблице должно быть возможно восстановить слова в исходном порядке; отдельная программная операция декодирования условием не задаётся. Имена классов, методы и способ ввода выберите самостоятельно. Вход для воспроизводимой проверки

Обязательные объявления входа заданы в стартере; сохраните их и свяжите со своим решением. Собственные классы, видимость, вспомогательные методы и алгоритмы выбирайте в пределах условия. Если предметный API уже обеспечивает этот вход, дополнительный класс не требуется.

Проверяется ваша кодовая таблица по частотам, префиксности, минимальной суммарной длине и последовательности входных слов. Единственная эталонная таблица, лексикографическое разрешение равенств и программный декодер не назначаются.

Открытые примеры

Для текста one two two three three three таблица содержит частоты one: 1, two: 2, three: 3 и двоичные префиксные коды. Взвешенная длина равна 9, а битовая последовательность совпадает с конкатенацией кодов шести слов в исходном порядке. Правило разрешения равных весов, включая внутренние узлы, объявляется заранее и воспроизводимо. Конкретные дерево, коды и порядок таблицы свободны.

Независимо кодируют пустой текст, one one one и red blue green. Для пустого текста таблица и биты пусты; для one one one единственный код — 0, биты — 000. В третьем тексте частоты равны 1, 1, 1, оптимальная длина равна 5. Повтор кодирования третьего текста с тем же выбранным правилом воспроизводит свой результат; другие допустимые коды законны.

Единственный файл решения — Study.java, без объявления пакета. Решение, вспомогательные классы и методы размещайте в нём.
