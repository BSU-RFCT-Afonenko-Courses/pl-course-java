Сложность: Высокий

Завершите предоставленное консольное приложение gradeapp. Реализуйте пять методов заготовки и предъявите работающий JAR с входными файлами и граничными примерами.

Команда и формат

Команда grade.Main input threshold получает ровно два аргумента: путь UTF-8-файла и целый порог 0–100. Относительный путь разрешается от рабочего каталога. Отчёт выводится в stdout, диагностика — в stderr. Предоставленная точка входа проверяет число аргументов, порог и синтаксис пути до чтения. Порог разбирается через Integer.parseInt без strip.

Каждая значимая строка файла содержит ровно три поля id;name;score. Кавычки и экранирование не используются. strip() удаляет краевые пробельные символы полей; балл разбирается как int. Строки, для которых isBlank() возвращает true, пропускаются. Физический номер начинается с 1 и учитывает каждую строку, включая пропущенные.

Предоставленная запись grade.Student(String id, String name, int score) нормализует id и name через strip; они непустые и не содержат ;, CR и LF. Балл находится в диапазоне 0–100. Нулевые ссылки id/name приводят к NullPointerException, остальные нарушения — к IllegalArgumentException. Равенство записи включает все три компонента. В каталоге нормализованные коды уникальны с учётом регистра: s1 и s1 — повтор, s1 и S1 — разные коды.

Методы для реализации

Методы размещены в предоставленных классах пакета grade. Сохраните их имена, доступ, параметры и возвращаемые типы. Проверяемые отказы должны оставаться в объявленной области throws: допустимое сужение сохраняет совместимость обычного вызывающего кода, который отдельно обрабатывает указанные исключения. Список проверяемых исключений, которые обязан учитывать клиент, расширяться не должен.

  • StudentParser: public static Student parse(String line, long number) throws DataFormatException. Предусловия — ненулевая строка и положительный физический номер. Проверьте три поля, сохраняя возможное пустое последнее поле. Неверное число или нарушение ограничений Student оберните в DataFormatException с исходной причиной NumberFormatException или IllegalArgumentException. Сообщение начинается с строка <number>: и поясняет отказ. Для неверного числа полей сообщите отдельную ошибку формата; причина для неё необязательна.
  • StudentFiles: public static List<Student> read(Path path) throws IOException, DataFormatException. Предусловие — ненулевой путь. Прочитайте UTF-8, пропустите пробельные строки, проверьте уникальность кодов. При повторе выбросьте DataFormatException с сообщением строка <number>: повтор кода <id>; причина для этого отказа необязательна. Отсутствие файла и повреждённый UTF-8 приводят к IOException. После успешного чтения и закрытия верните весь список в порядке входа. Пустой файл даёт пустой список. Список имеет самостоятельную структуру; add, remove, set и sort запрещены через UnsupportedOperationException. Частичный каталог при отказе не возвращается.
  • Reports: public static List<Student> selected(List<Student> students, int threshold). Предусловие — ненулевой список ненулевых допустимых Student. Порог вне 0–100 отклоняется через IllegalArgumentException, включая пустой вход. Отберите записи с score >= threshold; порядок — балл по убыванию, затем код по естественному порядку String. Состав и порядок исходного списка сохраняются. Результат имеет самостоятельную структуру: последующее изменение исходного списка его не меняет; add, remove, set и sort результата запрещены через UnsupportedOperationException. Неизменяемые элементы Student могут использоваться совместно; создание нового экземпляра списка само по себе не является требованием.
  • Reports: public static String line(Student student). Предусловие — ненулевой Student. Верните id;name;score без заголовка и перевода строки.
  • Main: static int run(Path input, int threshold) throws IOException, DataFormatException. Сохраните пакетный доступ. Для уже проверенных пути и порога свяжите чтение, отбор и предоставленный printReport; верните его статус. Вывод отчёта начинается после успешной загрузки и проверки всего каталога.

Внешний результат

Stdout содержит по одной строке id;name;score на выбранную запись, без заголовка. Пустой каталог и пустой отбор дают пустой stdout и успех. Коды завершения: 0 — успех; 2 — аргументы, порог или синтаксис пути; 3 — формат данных, диапазон балла или повтор кода; 4 — чтение или вывод. При ошибке данных либо чтения stdout пуст; stderr поясняет отказ. При отказе вывода уже переданная часть отчёта остаётся у получателя. Системные потоки должны оставаться открытыми.

Сборка и демонстрация

Нужны установленный Gradle 9.8.0 и JDK 25; JAVA_HOME указывает каталог JDK. Из каталога с build.gradle один раз подготовьте зависимости через сеть:

gradle prepareDependencies

До реализации TODO проверьте компиляцию и сборку JAR без выполнения проверок поведения:

gradle --offline assemble testClasses

После реализации выполните сборку с публичными проверками и запустите пример:

gradle --offline clean build
java -jar build/libs/gradeapp.jar samples/students.txt 80

Для запуска из другого рабочего каталога подставьте абсолютные пути:

java -jar /absolute/path/student/build/libs/gradeapp.jar /absolute/path/student/samples/students.txt 80

Пути с пробелами заключайте в кавычки. Аргументов приложения два: путь входа и порог. Заготовка с TODO компилируется; её проверки поведения должны пройти после реализации пяти методов.

Для строк s2;Lin;70, s3;Ann;90, s10;Ada;90 и порога 80 или 90 stdout содержит s10;Ada;90, затем s3;Ann;90. При равных баллах сравниваются коды как строки: s10 предшествует s3. Исходный порядок остаётся s2, s3, s10. При пороге 100 отбор пуст.

Покажите баллы 0 и 100, пустой и пробельный файл, коды с разным регистром, позднюю неверную строку после пробельной строки с номером 3, повтор после strip, отсутствующий файл, неверный порог до чтения и запуск JAR из другого каталога. Объясните проверку уникальности, самостоятельную структуру результата selected и границу начала вывода.

Открытые примеры

В UTF-8-файле записано s2;Lin;70\ns3;Ann;90\ns10;Ada;90\n, где \n обозначает LF. Настоящий JAR запускают по абсолютному пути из другого рабочего каталога, передав абсолютный путь входа и порог 80. Программа завершается с кодом 0, выводит в stdout сначала s10;Ada;90, затем s3;Ann;90, с платформенным переводом строки после каждой записи. Stderr пуст, входной файл сохраняется.

Для входа s1;Ada;90\n \n s1 ;Other;80\n и того же порога 80 программа завершается с кодом 3. Stdout пуст, stderr содержит ошибка данных: строка 3: повтор кода s1 с платформенным переводом строки. Строка из трёх пробелов пропускается, но учитывается в нумерации; входной файл остаётся прежним.
