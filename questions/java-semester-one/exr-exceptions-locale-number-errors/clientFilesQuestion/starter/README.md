Прочитайте UTF-8-файл, содержащий по одной записи на строку: текст числа, табуляцию и тег локали BCP 47. Например, строки `1,5` + табуляция + `ru-BY` и `2.5` + табуляция + `en-US` дают сумму `4.0` и среднее `2.0`. Дополнительных пробелов вокруг полей нет.

Создайте метод чтения с параметром `Path` и `throws IOException`, возвращающий записи с исходным текстом числа и локали. Отдельный этап проверяет формат записи, тег локали и число, разбирает число целиком согласно локали и вычисляет сумму и среднее. Носитель `Raw` из стартера предоставляет номер и исходный текст физической строки. Номер начинается с 1. Текст сохраняется без изменений, без завершающего перевода строки. Анализ выполняется в порядке физических строк. В записи ровно одна табуляция и два непустых поля. Пустая строка и лишнее поле — ошибки записи. Дополнительных пробелов вокруг полей во входе нет; вводить правила обрезки или проверки таких пробелов не требуется. Тег разбирается целиком через `Locale.Builder`. Для числа используется обычный числовой формат `NumberFormat` выбранной локали. Поддержка определяется штатным получением форматтера для этой локали, включая документированный выбор родительской локали и поддержку расширений. Например, поддерживаемый `en-US-u-nu-latn` допустим; отсутствие точного объекта Locale в `getAvailableLocales()` само по себе не является ошибкой. Если форматтер получить невозможно, это ошибка соответствующей записи. Не заменяйте тег локалью машины.

Число должно быть разобрано целиком. Неуспешный разбор или непрочитанный хвост, например `2.5tail`, вызывает ошибку. Строгий контроль групп разделителей сверх поведения обычного `NumberFormat` не требуется; условие не вводит собственную грамматику числа. NaN, бесконечности и числовое значение, преобразующееся в бесконечный `double`, недопустимы. Каждая запись проверяется отдельно: слишком большое положительное число и его отрицание не делают две неверные записи допустимыми. При первой ошибочной записи анализ завершается с её номером.

Конечными должны быть также итоговые сумма и среднее. Временное превышение диапазона при выбранном порядке сложения само по себе не является ошибкой данных, если окончательный результат конечен. Например, три десятичные записи `10^308`, `10^308`, `−10^308` имеют допустимую сумму `10^308`. Здесь степень обозначает полную десятичную запись в файле, а не требование поддерживать запись со знаком `^` или экспонентой. Для двух записей `9×10^307` итоговая сумма недопустима; ошибка итогового вычисления относится к последней физической строке, её причина сохранена. Ошибка отдельной записи имеет приоритет перед итоговым вычислением.

Выбор числового представления и способа вычислений свободен; `BigDecimal`, точная десятичная арифметика и конкретная схема суммирования не обязательны. При сравнении конечных результатов допускается погрешность `max(10^-12, 10^-12 × |ожидаемое значение|)`; `+0.0` и `−0.0` равнозначны. Проверки используют значения, для которых допустимые способы разбора и округления дают согласованный результат в этой погрешности, и не задают отдельной задачи о правильно округлённой сумме произвольной длины. Ограничение на число строк не вводится. Анализ получает список, возвращённый `read`; проверка искусственно повреждённых объектов `Raw` вне этого пути не требуется.
