Сложность: Высокий

Прочитайте UTF-8-файл, содержащий по одной записи на строку: текст числа, табуляцию и тег локали BCP 47. Например, строки 1,5 + табуляция + ru-BY и 2.5 + табуляция + en-US дают сумму 4.0 и среднее 2.0. Дополнительных пробелов вокруг полей нет.

Создайте метод чтения с параметром Path и throws IOException, возвращающий записи с исходным текстом числа и локали. Отдельный этап проверяет формат записи, тег локали и число, разбирает число целиком согласно локали и вычисляет сумму и среднее. Синтаксическую корректность тега проверяйте через Locale.Builder; локаль должна поддерживаться NumberFormat. NaN, бесконечности и результат за пределами конечного double недопустимы.

Определите собственное проверяемое исключение для ошибочной записи с номером строки и причиной. При ошибке прекратите обработку; для пустого файла сообщите об отсутствии данных, среднее не вычисляйте. Проверьте неверное число, пустое поле, неверный тег, слишком большое число и отсутствие файла. Чтение реализуется по этому условию; готовый компонент не предоставляется.

Предъявите использованные входные файлы, результат обычной обработки и отказы из условия. Объясните границу между чтением и проверкой записи, номер ошибочной строки и сохранение причины. Имена классов и методов, представление записей, способ передачи пути и формат вывода выберите самостоятельно.

Сохраните обязательные сигнатуры открытого класса Study из канонического стартера, без объявления пакета. Решение можно разместить в нём или вызвать из него свои классы и методы. Дополнительный класс запуска и фиксированный формат демонстрации не требуются.

Через операции read и analyze из стартера обеспечьте два отдельных этапа. Чтение получает Path, возвращает исходные записи и сохраняет границу IOException. Анализ получает прочитанные записи и возвращает количество, сумму и среднее либо собственное проверяемое исключение ошибочной записи.

Носитель Raw из стартера предоставляет номер и исходный текст физической строки. Номер начинается с 1. Текст сохраняется без изменений, без завершающего перевода строки. Табуляции, пустые поля и пустые физические строки сохраняются. Завершающий перевод строки завершает последнюю строку, дополнительную запись после него создавать не нужно. Чтение возвращает записи до проверки их формата и содержимого: повреждённая запись обнаруживается на этапе анализа. Для чтения LF и CRLF являются разделителями строк. Файловые отказы остаются IOException или его подклассами.

Носитель Summary из стартера предоставляет число записей, сумму и необязательное среднее. Для непустого файла это количество записей, их сумма и среднее; для пустого файла количество равно 0, среднее отсутствует, поле суммы не оценивается. В собственной демонстрации сообщите об отсутствии данных. Собственное внутреннее представление записей и результатов свободно.

Проверяемое исключение BadRecord из стартера предоставляет номер ошибочной строки и ненулевую причину через getCause(). Причиной служит исходное исключение проверки либо созданное объяснение конкретного нарушения. Собственный внутренний тип может быть и проверяемым подклассом IOException; конструкторы, класс причины и текст сообщения свободны.

Анализ выполняется в порядке физических строк. В записи ровно одна табуляция и два непустых поля. Пустая строка и лишнее поле — ошибки записи. Дополнительных пробелов вокруг полей во входе нет; вводить правила обрезки или проверки таких пробелов не требуется. Тег разбирается целиком через Locale.Builder. Для числа используется обычный числовой формат NumberFormat выбранной локали. Поддержка определяется штатным получением форматтера для этой локали, включая документированный выбор родительской локали и поддержку расширений. Например, поддерживаемый en-US-u-nu-latn допустим; отсутствие точного объекта Locale в getAvailableLocales() само по себе не является ошибкой. Если форматтер получить невозможно, это ошибка соответствующей записи. Не заменяйте тег локалью машины.

Число должно быть разобрано целиком. Неуспешный разбор или непрочитанный хвост, например 2.5tail, вызывает ошибку. Строгий контроль групп разделителей сверх поведения обычного NumberFormat не требуется; условие не вводит собственную грамматику числа. NaN, бесконечности и числовое значение, преобразующееся в бесконечный double, недопустимы. Каждая запись проверяется отдельно: слишком большое положительное число и его отрицание не делают две неверные записи допустимыми. При первой ошибочной записи анализ завершается с её номером.

Конечными должны быть также итоговые сумма и среднее. Временное превышение диапазона при выбранном порядке сложения само по себе не является ошибкой данных, если окончательный результат конечен. Например, три десятичные записи 10^308, 10^308, −10^308 имеют допустимую сумму 10^308. Здесь степень обозначает полную десятичную запись в файле, а не требование поддерживать запись со знаком ^ или экспонентой. Для двух записей 9×10^307 итоговая сумма недопустима; ошибка итогового вычисления относится к последней физической строке, её причина сохранена. Ошибка отдельной записи имеет приоритет перед итоговым вычислением.

Выбор числового представления и способа вычислений свободен; BigDecimal, точная десятичная арифметика и конкретная схема суммирования не обязательны. При сравнении конечных результатов допускается погрешность max(10^-12, 10^-12 × |ожидаемое значение|); +0.0 и −0.0 равнозначны. Проверки используют значения, для которых допустимые способы разбора и округления дают согласованный результат в этой погрешности, и не задают отдельной задачи о правильно округлённой сумме произвольной длины. Ограничение на число строк не вводится. Анализ получает список, возвращённый read; проверка искусственно повреждённых объектов Raw вне этого пути не требуется.

Открытые примеры

Чтение исходных строк. В UTF-8 файле две строки:

1,5 ru-BY
2.5 en-US

Между числом и тегом локали находится одна табуляция. Вызов read возвращает обе исходные строки без изменений.

Сумма и среднее. Примените read, затем analyze к тому же файлу. Число записей равно 2, сумма — 4, среднее — 2.

Пустой файл. Для существующего UTF-8 файла размером 0 байт после чтения и анализа число записей равно 0, среднее отсутствует. Сообщение собственной демонстрации об отсутствии данных проверяется вручную.

Сдайте Study.java без объявления пакета, сохранив объявления входа из стартера.
