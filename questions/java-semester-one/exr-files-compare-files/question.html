Создайте утилиту CompFiles, предназначенную для сравнения двух файлов. При запуске имена файлов передаются в командной строке. Утилита открывает оба файла, затем читает и сравнивает соответствующие байты. При обнаружении несовпадения файлы считаются различными. Если концы файлов достигнуты одновременно и несовпадений не было, файлы считаются совпадающими. Используйте try с ресурсами для автоматического закрытия файлов.

Для этой практической работы сравнивайте обычные текстовые файлы; результат сравнения выведите на консоль.

Для проверки подготовьте два одинаковых UTF-8-файла со строкой «Java text» и третью версию «Java test». Добавьте пару с одинаковым началом и разной длиной.

Передайте ровно два пути; относительные пути разрешаются от рабочего каталога. Входные файлы остаются неизменными. Пустые файлы совпадают; пустой и непустой различаются. Отказ открытия или чтения сопровождается диагностикой и отдельным исходом: вывод о равенстве в этом случае не делается. Покажите также отсутствующий файл. Текст сообщений выберите самостоятельно.

Предъявите исходник и использованные пары файлов. Покажите try с ресурсами и объясните, как различаются конец файла и ошибка чтения.

Вход для воспроизводимой проверки

Сохраните обязательные сигнатуры входов из стартера. Они связывают проверку с вашим решением; наблюдаются его фактические действия и результаты. Формат отчёта и диагностики выбирайте в пределах условия.

Открытые примеры

Программе CompFiles передают пути двух UTF-8-файлов, каждый из которых содержит Java text без конечного LF. Она сообщает, что файлы совпадают, и сохраняет оба входа.

Если первый файл содержит Java, а второй — Java text, также без конечного LF, программа сообщает различие. Общее начало не делает файлы равными; это результат сравнения, а не файловый отказ. Оба входа сохраняются.

Для сдачи используйте два редактора: CompFiles.java и Study.java, без объявления пакета. Сохраните объявления входа из стартера; вспомогательные классы и методы размещайте в этих файлах.
