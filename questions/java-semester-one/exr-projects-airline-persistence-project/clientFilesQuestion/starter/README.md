<a id="exr-projects-airline-persistence-project"></a>

Разработайте консольное приложение для учёта самолётов авиакомпании. По составу парка оно должно вычислять суммарные характеристики, упорядочивать самолёты и находить подходящий по расходу топлива. Сохранённые сведения должны быть доступны после загрузки из файла.

Подготовка: классы и инкапсуляция ([Глава 11](https://bsu-rfct-afonenko-courses.github.io/Java/theory/classes.html#sec-theory-classes)), наследование и полиморфизм, массивы и файловый ввод-вывод. При выборе коллекции для хранения парка используйте [Глава 18](https://bsu-rfct-afonenko-courses.github.io/Java/theory/collections.html#sec-theory-collections). Перед сохранением модели разберите сериализацию объектов Java и назначение `static` и `transient` при выбранном способе записи. Сначала получите результаты операций с парком в памяти; затем сопоставьте их с результатами после сохранения и загрузки.

<div>

<a id="данные-и-операции"></a>

#### Данные и операции

</div>

Определите иерархию самолётов и объект авиакомпании, содержащий парк. Минимальный набор состоит из трёх самолётов с уникальными идентификаторами:

| Вид | Вместимость, мест | Грузоподъёмность, т | Дальность, км | Потребление, л/ч |
|----|---:|---:|---:|---:|
| Пассажирский | 150 | 12 | 3000 | 2400 |
| Грузовой | 2 | 20 | 4500 | 3000 |
| Пассажирский | 80 | 6 | 1800 | 1500 |

Данные учебные. Используйте предметные единицы последовательно. Возможности приложения:

- подсчёт общей вместимости и грузоподъёмности всех самолётов компании;
- сортировка самолётов по дальности полёта;
- поиск самолёта, потребление горючего которого входит в заданный диапазон с включёнными границами;
- сохранение и загрузка объектов приложения в одном или нескольких файлах с применением сериализации Java;
- изменение и извлечение сохранённых сведений через отдельный класс-коннектор.

Коннектор должен сохранять обновлённую модель: после изменения параметра самолёта и повторной загрузки приложение получает новое значение. Способ сериализации, имена файлов данных и сигнатуры операций выберите самостоятельно. Объекты могут содержать `static`- и `transient`-поля; покажите и объясните их значения после загрузки с учётом выбранного способа сериализации.

</div>

Используйте классы, инкапсуляцию, наследование и полиморфизм. Иерархия должна отражать виды самолётов; названия классов и их состав — предметные роли. Распределите классы по пакетам и соблюдайте Java Code Conventions. Консольное меню достаточно ограничить операциями задачи. Параметры инициализации при желании можно хранить в файлах.

Перед демонстрацией назовите выбранные направление сортировки и способ сериализации. Предъявите исходники и использованные данные. Для исходного набора проверьте суммы, порядок по дальности и отбор в диапазоне `[1500, 2400]`. Затем сохраните и загрузите парк, измените сведения через коннектор и повторите загрузку. По наблюдениям объясните, какие данные составляют сохраняемое состояние самолёта и как ведут себя выбранные `static`- и `transient`-поля. [\[1\]](#ref-bib-task-airline-persistence-project)

### Открытые примеры

Исходный парк состоит из трёх самолётов с уникальными идентификаторами: пассажирского на 150 мест с грузоподъёмностью 12 т, дальностью 3000 км и расходом 2400 л/ч; грузового с 2 местами, 20 т, 4500 км и 3000 л/ч; пассажирского на 80 мест с 6 т, 1800 км и 1500 л/ч. Направление сортировки, сериализацию и файлы выбирают заранее. Суммарно получаются 232 места и 38 т; при проверке суммы грузоподъёмности допустимо абсолютное отклонение `1e-9`. Сортировка даёт дальности `1800, 3000, 4500` либо обратный порядок — согласно выбранному направлению. Поиск расхода в `[1500, 2400]` находит один или несколько подходящих самолётов. После сохранения и загрузки сохраняются виды и параметры всех самолётов. Изменение числа мест третьего самолёта на `100` через коннектор видно после новой загрузки; сумма мест становится `252`, грузоподъёмность остаётся 38 т.

В независимом исходном парке поиск `[1500, 1500]` находит пассажирский самолёт с расходом 1500 л/ч, `[2400, 2400]` — пассажирский с расходом 2400 л/ч. Для `[4000, 4100]` совпадений нет. Форма результата поиска свободна.

**Если выбрана стандартная сериализация**

При стандартном сохранении полей обычного класса `Serializable` в поток входят его нестатические поля без `transient`. Это правило относится к стандартному набору полей; собственное описание сохраняемых полей и код записи могут задавать другие действия. При стандартном восстановлении сохранённые значения берутся из потока. Поля `transient` первоначально получают значения по умолчанию; собственный код восстановления может установить другие значения. Поля `static` принадлежат классу в JVM и не входят в стандартный набор сохраняемых полей. [Состав полей: разделы 1.5 и 1.7](https://docs.oracle.com/en/java/javase/25/docs/specs/serialization/serial-arch.html#defining-serializable-fields-for-a-class).

При десериализации такой иерархии обычных классов вызывается конструктор без аргументов первого несериализуемого суперкласса; его поля инициализируются этим конструктором. [Восстановление: §3.1, шаг 12](https://docs.oracle.com/en/java/javase/25/docs/specs/serialization/input.html#the-objectinputstream-class). При собственной записи и восстановлении состояния объясните выбранные действия.
